# 富渲染协议规范 v1

> 版本：1.0.0（草案）　　日期：2026-11-05
> 配套文档：`docs/rich-render-technical-plan-2026-11.md`
> 状态：待评审。**本规范先行，DSH 插件与安卓端各自照此实现**

---

## 0. 这份规范解决什么问题

技术方案里定了两件事：**上色（渲染层）** 和 **结构改版（渲染层 + 内容层）**。

上色不需要协议——渲染层自己识别语义就行。**结构改版必须有协议**，否则模型和渲染层各说各话。

这份规范定义：
1. 模型用什么标记表达结构
2. 渲染层怎么解析成卡片/表格/步骤流
3. **解析不了、模型不配合、流式到一半时怎么降级**（第 6、7 章，最重要）

---

## 1. 设计原则

| # | 原则 | 理由 |
|---|---|---|
| 1 | **优雅降级永远优先于正确渲染** | 模型不配合是常态，不是异常。界面崩了就是 bug |
| 2 | **不新增模型负担** | 优先复用训练数据里已有的语法（GitHub Alerts），模型零学习成本 |
| 3 | **标记要可读** | 出错时用户看到的是原文，不是乱码 |
| 4 | **结构按需启用** | 不是每条回复都该变成卡片，由内容层判断 |
| 5 | **渲染层与内容层解耦** | 换宿主（DSH → 安卓）只换渲染层，协议不变 |
| 6 | **token 成本可控** | 结构标记不能让回复膨胀 50% 以上 |

## 2. 标记族总览

两族标记，共用一个围栏语法。

| 族 | 用途 | 语法来源 | 模型配合度 |
|---|---|---|---|
| **S 族**（Semantic） | 语义色块：补充/建议/警告/结论 | **直接复用 GitHub Alerts** | 高，训练数据里到处都是 |
| **X 族**（Extended） | 结构块：结论卡/要点卡/表格/步骤流/分栏 | 本规范自定义 fence | 中，需 skill 教 |

### 2.1 围栏语法

X 族统一用 `:::` 三冒号围栏（比 ` ``` ` 多一级，避免和代码块混淆）：

```
:::块类型{属性="值"}
内部内容
:::
```

**为什么用 `:::` 而不是 ` ``` `：** ` ``` ` 已经是代码块，再复用会导致嵌套歧义（代码块里怎么写 fence？）。三冒号在实践中几乎不会与代码冲突。

## 3. S 族 · 语义块

### 3.1 语法

标准 GitHub Alerts 语法，**原样使用，不做任何扩展**：

```markdown
> [!NOTE]
> 补充说明内容。

> [!TIP]
> 实用建议。

> [!WARNING]
> 风险提醒。

> [!IMPORTANT]
> 关键结论。
```

### 3.2 语义与视觉映射

| 类型 | 语义 | 底色（亮/暗） | 左边框 | 标签文字 |
|---|---|---|---|---|
| `NOTE` | 补充说明 | `#E6F1FB` / `#253244` | `#185FA5` / `#378ADD` | 补充说明 |
| `TIP` | 建议技巧 | `#E1F5EE` / `#1D3D31` | `#0F6E56` / `#1D9E75` | 实用建议 |
| `WARNING` | 风险警告 | `#FAEEDA` / `#3D3115` | `#854F0B` / `#BA7517` | 注意事项 |
| `IMPORTANT` | 关键结论 | `#FCEBEB` / `#3D1C1C` | `#A32D2D` / `#E24B4A` | 关键结论 |

**颜色只是建议值**，具体实现可换，**语义映射关系不可改**。

### 3.3 扩展类型（容错处理）

允许模型输出未定义的类型（如 `[!SUCCESS]`、`[!CAUTION]`）：

- 渲染层**必须**不崩溃
- 降级为 `NOTE` 样式，标签显示原文类型名（去掉 `!`）
- 记一条 warning 日志

## 4. X 族 · 结构块

### 4.1 `:::summary` 结论卡

内容最重要的信息，放在回复最前面。

```markdown
:::summary{title="结论"}
丢失的是**可定位坐标**，不是数据本身。多数场景无关紧要，全程依赖的场景才需显式保留。
:::
```

**属性**

| 属性 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `title` | 否 | `结论` | 卡片标题 |
| `tone` | 否 | `info` | `info` / `success` / `warn` / `danger` / `neutral` |

**渲染**：左侧 3px 竖条 + 极浅底色 + 标题 + 正文段落。

**约束**：正文只允许**段落级** markdown（加粗、行内代码、链接）。**不允许嵌套其他块**。

---

### 4.2 `:::points` 要点卡组

把并列要点拆成卡片组。

```markdown
:::points{cols="3"}
- **数据在** — ref 会读写，ttl>0 即会话存活
- **入口没了** — 页面方式取不回，需重新编号
- **uuid 不可转** — 无法塞进另一条对循环
:::
```

**内部语法**：markdown 无序列表，每项格式为 `**标题** — 描述`
（`-` / `—` / `：` / `:` 均可作为分隔符，解析时统一处理）

**属性**

| 属性 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `cols` | 否 | `3` | 卡片列数。窄屏自动降级为 1 列（≤640px 视口） |
| `tone` | 否 | `neutral` | 卡片左侧圆点颜色组 |

**降级**：解析不出标题/描述时，整块退回普通 markdown 列表。

---

### 4.3 `:::table` 对比表

```markdown
:::table{title="影响面"}
| 场景 | 影响 | 处理 |
|---|---|---|
| 多数时候 | 无关紧要 | 无需处理 |
| 全程依赖 | 必须锁写 | 显式保留定位信息 |
:::
```

**内部语法**：标准 markdown 表格。**分隔行 `|---|---|` 必须存在**，否则视为无效。

**属性**

| 属性 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `title` | 否 | 无 | 表格上方标题 |
| `compact` | 否 | `false` | `true` 时减小单元格内边距 |

**约束**：宽表在窄屏下**横向滚动**，不换行、不压缩列宽。

---

### 4.4 `:::steps` 步骤流

```markdown
:::steps{title="三条规避", ordered="按推荐排序"}
1. 压缩时保留定位信息
2. 先取所需再让它压后面
3. 大输出优先抽查、用摘要引用
:::
```

**内部语法**：markdown 有序列表。无序列表也接受，渲染时不显示序号。

**属性**

| 属性 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `title` | 否 | 无 | 标题 |
| `ordered` | 否 | 无 | 副标题（如"按推荐排序"），**不改变渲染逻辑** |
| `showLine` | 否 | `true` | 是否显示步骤间连接线 |

**渲染**：序号圆点 + 连接线 + 标题 + 描述。

---

### 4.5 `:::columns` 分栏

```markdown
:::columns
左栏内容……

---
右栏内容……
:::
```

**内部语法**：以独占一行的 `---` 分隔左右两栏。超过 2 栏时只取前 2 栏，其余降级为纵向追加。

**约束**：窄屏（≤640px）自动降级为上下堆叠。分栏内不允许嵌套分栏。

## 5. 内容层 · Skill 规范

渲染层能解析 ≠ 模型会输出。**必须写一个 skill 教模型**，规则如下。

### 5.1 判断规则（关键）

模型在生成回复时，先判断内容类型：

| 内容特征 | 用什么 |
|---|---|
| 单一最重要结论 | `:::summary` |
| 2-5 个并列要点 | `:::points` |
| 两个及以上维度的对比 | `:::table` |
| 有先后顺序的操作步骤 | `:::steps` |
| 常规解释、代码、报错 | **什么都不用，输出普通 markdown** |

**默认什么都不用。** 这是最重要的约束——结构是例外，不是常态。

### 5.2 Skill 正文骨架

```markdown
# 富渲染输出规范

你在为一个支持结构化渲染的界面生成回复。

## 何时使用结构
仅当回复内容明确属于以下四类之一时，才使用对应标记。
其余情况（解释、代码、报错分析、闲聊、列表列举）一律输出普通 markdown。

## 标记
- 结论摘要：:::summary{title="结论"} ... :::
- 并列要点：:::points{cols="N"} - **标题** — 描述 ... :::
- 对比表格：:::table{title="..."} | 列1 | 列2 | ... ::::
- 步骤流程：:::steps{title="..."} 1. ... ::::

## 硬性规则
1. 每个块内部不得嵌套同类块
2. 块与块之间空一行
3. 一个回复里同类块最多 2 个（summary 除外）
4. 不要为了用块而用块——普通 markdown 永远是被允许的
5. 代码块、表格、引用块内部不得出现 ::: 围栏
```

### 5.3 完整示例（给模型看的 few-shot）

```
用户问：ref 编号丢了会怎样？

输出：
:::summary{title="结论"}
丢失的是**可定位坐标**，不是数据本身。多数场景无关紧要。
:::

:::points{cols="3"}
- **数据在** — ref 会读写，ttl>0 即会话存活
- **入口没了** — 页面方式取不回，需重新编号
- **uuid 不可转** — 无法塞进另一条对循环
:::

正文继续正常 markdown…
```

## 6. 流式渲染契约 ★

**这是最容易翻车的地方。** 模型是流式吐字的，一个 `:::summary{title="结论"}` 可能在几十毫秒后才闭合。这期间界面不能闪、不能跳。

### 6.1 三种中间态

| 状态 | 判定条件 | 渲染表现 |
|---|---|---|
| **未闭合** | 收到 `:::` 起始围栏但还没收到结束围栏 | 渲染为**普通引用块**样式（`>` 引用），或半成品卡片 |
| **刚闭合** | 收到结束围栏 | 切换为完整卡片，**一次性切换，不做动画** |
| **闭合后追加** | 块已闭合，后续又有内容 | 块保持不变，新内容正常渲染 |

### 6.2 硬性要求

1. **不闪烁**：未闭合态和闭合态的**宽度、高度必须一致**，或用固定最小高度占位。禁止缩放动画、禁止渐显。
2. **不阻塞**：未闭合的块**必须立即渲染**，不能等闭合才显示。等待 = 用户以为卡死了。
3. **不重复**：块闭合时**替换**未闭合态的内容，不是追加。
4. **可中断**：用户停止生成时，未闭合的块按未闭合态保留（不丢弃、不报错）。
5. **无块标记时的流式**：普通 markdown 照常增量渲染，不受本规范影响。

### 6.3 实现建议

用「**缓冲 + 替换**」而非「增量修改」：

```
收到 chunk
  ↓
追加到缓冲区
  ↓
检测缓冲区末尾是否有未闭合的 ::: 围栏
  ├─ 无 → 渲染完整缓冲区
  └─ 有 → 截断到最后一个完整块，剩余部分按未闭合态渲染
```

代价是块闭合瞬间会有一次内容重排，但避免了增量修改的复杂状态机。**宁可重排，不要闪烁。**

## 7. 降级矩阵 ★

**模型不配合是常态。** 本章是本规范最重要的部分。

### 7.1 降级层级

从 L0（完全结构化）逐级降到 L4（纯文本）：

| 层级 | 条件 | 表现 |
|---|---|---|
| **L0** | 解析成功，字段完整 | 完整卡片/表格/步骤流 |
| **L1** | 解析成功，个别可选字段缺失 | 用默认值补齐，结构保留 |
| **L2** | 围栏闭合，但内部结构不符合规范（如表格缺分隔行） | **整块**退回普通 markdown 渲染（保留原文，不报错） |
| **L3** | 围栏未闭合且流已结束 | 按未闭合态渲染为引用块，末尾不加错误提示 |
| **L4** | 模型完全没输出标记 | 原样渲染普通 markdown（= 现状，即宿主默认行为） |

**关键：L2/L3 都不允许显示任何错误提示给用户。** 用户不关心你的协议解析失败，只关心内容。

### 7.2 逐块降级矩阵

| 块类型 | 字段缺失时的行为 | 结构非法时的行为 |
|---|---|---|
| `summary` | `title` 缺失 → 用默认"结论" | 正文为空 → 整块丢弃 |
| `points` | `cols` 缺失 → 用 3 | 无法解析出「标题+描述」→ 整块退回 markdown 列表 |
| `table` | `title` 缺失 → 不显示标题 | 缺分隔行 / 无数据行 → 整块退回原始表格文本 |
| `steps` | `title` 缺失 → 不显示标题 | 无有效列表项 → 整块退回 markdown 列表 |
| `columns` | — | 分隔符数量 ≠ 1 → 整块退回普通内容 |

### 7.3 全局兜底

1. 渲染层**永不抛异常到宿主**。任何解析错误就地捕获，记日志，返回降级结果。
2. 解析器实现必须有单元测试覆盖「非法输入」用例——**非法输入是主要路径，不是边缘情况**。
3. 宿主若提供了 markdown 渲染原语（如 DSH 的 `MarkdownText`），降级路径**直接用它**，不自己写 markdown 渲染器。

## 8. 转义与嵌套

### 8.1 转义

正文里需要出现 `:::` 时：

```markdown
\:::summary
```

渲染层识别到 `\:::` 时按字面输出，不解析为块。

### 8.2 嵌套限制

| 规则 | 说明 |
|---|---|
| 同类块不嵌套 | `points` 里不能有 `points` |
| `summary` 内不允许任何块 | 只允许段落级 markdown |
| 表格/步骤流内不允许块 | 只允许纯文本 + 行内 markdown |
| `columns` 内不允许 `columns` | 最多 2 栏 |
| **最大嵌套深度 = 1** | 任何块内部不再出现任何块 |

违反嵌套规则 → 该块按 L2 降级为普通 markdown。

### 8.3 代码块内的 `:::` 豁免

**围栏内的 `:::` 一律不解析。** 这是硬规则，优先于所有其他规则。

```markdown
```
:::summary
这段在代码块里，不解析
:::
```
```

## 9. 渲染层 API 契约

两端（DSH 插件 / 安卓端）实现同一套接口，**签名语义一致**。

```ts
type Tone = 'info' | 'success' | 'warn' | 'danger' | 'neutral'

interface Block {
  type: 'summary' | 'points' | 'table' | 'steps' | 'columns'
  attrs: Record<string, string>
  raw: string          // 原始内容
  level: 0 | 1 | 2 | 3 | 4   // 降级层级
}

interface ParseResult {
  blocks: Block[]
  trailing: string     // 末尾未闭合部分
}

// 主入口：把整段文本切成 blocks + 普通 markdown 段
function parseRich(text: string): Segment[]

type Segment =
  | { kind: 'markdown'; content: string }
  | { kind: 'block'; block: Block }
```

**关键约定**

| 函数 | 行为 |
|---|---|
| `parseRich` | **永不抛异常**。任何异常 → 返回 `[{kind:'markdown', content: 原文本}]` |
| `Block.level` | 渲染层据此决定用结构样式还是降级样式 |
| `parseRich` | 纯函数，无副作用，可单测 |

### 9.1 DSH 侧落点

| 环节 | DSH 扩展点 |
|---|---|
| 拿流式文本 | `ctx.on('agent/assistant-stream')` 或 `session/event` |
| 接管 assistant 渲染 | `ctx.slots.register({name:'conversation.chat.node', key:'assistant', priority:-10}, Component)` |
| 主题 token | `ctx.theme.overrideTokens(id, {token: {light, dark}})` |
| 挂浮动面板 | `ctx.slots.inject('shell.overlay', ...)` |

### 9.2 安卓侧落点

| 环节 | Android 实现 |
|---|---|
| 流式解析 | 在 ViewModel 层对累积文本跑 `parseRich` |
| 渲染 | `multiplatform-markdown-renderer` 的 `markdownComponents()` 逐节点覆盖 |
| 语义块 | GitHub Alerts 原生支持，S 族几乎零成本 |
| 自定义块 | 实现 `markdownComponents(codeFence = ...)` 类似的节点覆盖 |
| 流式稳定性 | `rememberStreamingMarkdownState()` + `retainState = true` |

## 10. token 成本与选择性启用

### 10.1 成本估算

| 场景 | 结构标记 token 增量 |
|---|---|
| 单个 summary | +15 |
| 3 个 points | +40 |
| 2 列表格 | +25 |
| 3 步 steps | +30 |
| **整条回复全结构化** | **+80 ~ +120（相对 300 token 的回复约 +30%）** |

### 10.2 控制手段

1. **同类块最多 2 个**（summary 除外）——已在 skill 里约束
2. **只在"信息密度高"的回复启用**——代码、报错分析、闲聊一律不启用
3. **不需要结构时正常输出**——这是模型该有的默认行为

### 10.3 可选：JSON schema 模式

DSH 支持结构化输出协议（`system-prompt/assemble` 段贡献）。若走这条路：

- 模型输出 JSON 而非 markdown fence
- 渲染层直接反序列化，**无解析歧义**
- 代价：token 消耗更高，且模型无法在 JSON 里混排自由文本

**建议：v1 用 fence 语法，v2 再评估 JSON。** fence 的好处是模型不配合时天然退回 markdown，JSON 做不到这点。

## 11. 版本与兼容

- 协议版本独立于宿主版本。DSH 插件的 `package.json` 里 `dsh.engines.dsh` 管宿主兼容，协议版本另标。
- **新增块类型 = MINOR**（老渲染器遇到不认识的类型 → L2 降级，不崩）
- **修改已有块语义 = MAJOR**
- 渲染层实现必须支持「遇到未知 type → 当普通 markdown 输出」

| 2 | `:::summary\n内容\n:::` | 1 个 summary 块，title = "结论"（默认），level 1 |

| 4 | `:::table{title="影响面"}\n\| a \| b \|\n\|---\|---\|\n\| 1 \| 2 \|\n:::` | 1 个 table 块，level 0 |
| 4b | 同上但**无** `title` 属性 | level 1（默认值补齐） |
| 5 | `:::steps\n1. 一\n2. 二\n:::` | 1 个 steps 块，2 项 |
| 6 | `:::columns\n左\n\n---\n\n右\n:::` | 1 个 columns 块，2 栏 |
| 7 | `普通段落\n\n第二段` | **1 个** markdown 段（连续行合并） |

### 12.2 降级（主要路径）

| # | 输入 | 期望 |
|---|---|---|
| 8 | `:::table\n\| a \| b \|\n无分隔行\n:::` | level 2，渲染为普通文本 |
| 9 | `:::points\n没有加粗也没有分隔符\n:::` | level 2，退回 markdown 列表 |
| 10 | `:::summary{title="x"}\n内容`（未闭合，流结束） | level 3，渲染为引用块 |
| 11 | `:::unknown{foo="bar"}\n内容\n:::` | level 2，退回普通文本 |
| 12 | `:::summary\n`（空块） | 整块丢弃 |
| 13 | 正常 markdown | level 4 / 无块（默认路径） |

### 12.3 边界

| # | 输入 | 期望 |
|---|---|---|
| 14 | 代码块内含 `:::` | 不解析为块（硬规则优先） |
| 15 | `\:::summary` | 字面输出 `:::summary` |
| 16 | 块内嵌套块 | 该块整体按 L2 降级 |
| 17 | 流式：逐字符喂入 `:::summary{x}\n内容\n:::` | 中间态为 L3（markdown 兜底），闭合后 level 0，**不产生块**直到闭合 |
| 18 | 输入为空字符串 | 返回空数组，不抛异常 |
| 19 | 输入只有 `:::` | 不抛异常 |
| 20 | 10000 字超长块 | 正常解析，不超时 |

### 12.4 渲染层不变量

| # | 断言 | 实测 |
|---|---|---|
| 21 | 对**任意**输入（fuzz 3000 组拼接），`parseRich` 不抛异常 | ✅ |
| 22 | 流式过程中块区域宽度变化 ≤ 1px（不跳动） | 需在各端渲染层验证 |
| 23 | 流式最终闭合为块，闭合前不产生块 | ✅ |

## 15. 实施过程中的经验（2026-11-05 补充）

规范不是空想——写完后立刻做了参考实现 + 测试，**测试当场抓出了三处问题**，记录在此供后续参考。

### 15.1 测试抓出的真问题

| 问题 | 性质 |
|---|---|
| **嵌套检测未实现** | 测试用例 16 原本写成 `t(16, '...', true)` —— 假通过。补上 `hasNestedBlock()` 后真正生效 |
| **用例 4 断言与输入不一致** | 实现按规范：无 `title` → L1，测试却断言 L0。**是测试写错，不是实现错** |
| **用例 7 误判段数** | `普通段落\n\n第二段` 是**1 个** markdown 段（连续行合并），不是 2 个 |

**教训**：写降级测试时，**断言必须逐字对应实现的 level 语义**。这类错误不会让代码崩，但会让"测试全绿"变成假信号——比没有测试更危险。

### 15.2 「非法输入是主路径」得到验证

24 个用例里，**降级相关占 10 个**（§12.2 + §12.3 边界），解析正确的只占 7 个。这个比例是对的——真实使用中模型不配合是常态，非法输入必须被当成主要场景测。

fuzz 测试用 9 个种子串两两拼接出 3000 组输入，验证 `parseRich` 永不抛异常。这一条通过了，说明 `try/catch` 兜底 + 各处 `filter` 兜底是够的。

### 15.3 流式的真实行为

逐字符喂入 `:::summary{title="结论"}\n内容\n:::` 实测：

- **闭合前**：`parseRich` 返回 0 个块、1 个 markdown 段（整段当未闭合文本）
- **闭合后**：返回 1 个块，level 0

这正好对应规范 §6.1 的「未闭合 → 按普通 markdown 渲染」设计。**渲染层只需实现：markdown 段照常渲染，遇到 level 0 的块才切换成卡片样式。** 不需要额外的中间态组件——这是个好消息，实现复杂度比预想低。
